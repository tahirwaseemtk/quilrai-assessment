# Task 2: MCP security gateway (auth + tool filtering)

Status: In progress (2.1 mock downstream, 2.2 client auth, 2.3 envelope validation, 2.4 passthrough proxy done)

## Setup and run

```sh
npm ci
npm run task2:mock     # mock downstream MCP server on 127.0.0.1:8081 (needs DOWNSTREAM_AUTH_TOKEN)
npm run task2          # gateway on 127.0.0.1:8080 -> DOWNSTREAM_MCP_URL (needs GATEWAY_TOKENS, DOWNSTREAM_AUTH_TOKEN)
npm run test:task2
```

Copy `.env.example` to `.env` and replace the placeholder tokens (the gateway warns at startup while they are in use). Settings: `GATEWAY_PORT` (8080), `DOWNSTREAM_MCP_URL` (`http://127.0.0.1:8081/mcp`), `DOWNSTREAM_TIMEOUT_MS` (5000, wait for downstream headers), `GATEWAY_TOKENS` (JSON token-to-role map), `DOWNSTREAM_AUTH_TOKEN` (the gateway's own downstream credential).

## Design

- **Mock downstream** ([ADR 018](../decisions/018-mock-downstream-mcp-server.md)): a real SDK MCP server over Streamable HTTP (stateless, JSON responses; SSE optional) at `POST /mcp`.
  - Tools: `get_status`, `admin_reset_key`, `admin`.
  - It accepts only the gateway's downstream credential, so a forwarded client token fails with 401.
  - A call spy records the tools that actually ran, so tests can prove a blocked call never reached it.
- **Bearer parsing** (`src/bearer.ts`): exactly `<scheme> <token>`, with a case-insensitive scheme, RFC 6750 `token68` token characters, and a constant-time comparison over SHA-256 digests. It is shared by the mock and the gateway.
- **Client auth** ([ADR 019](../decisions/019-gateway-client-auth.md)):
  - `GATEWAY_TOKENS` maps tokens to `admin` or `viewer` and is parsed by `src/token-config.ts`. Only SHA-256 digests are kept, and bad config fails with fixed reasons. Placeholder or short tokens are accepted with a warning, logged at startup from 2.4.
  - `authenticate` (`src/auth.ts`) takes only the `headersDistinct` shape, refuses duplicate `Authorization` headers, and compares against every configured token in constant time, with no early exit.
- **Envelope classification** ([ADR 020](../decisions/020-gateway-envelope-classification.md)): `classifyBody` (`src/envelope.ts`) answers malformed input itself, using the envelope checks shared with Task 1 (`shared/`).
  - Malformed JSON gets `-32700`; an invalid envelope, any batch, **any duplicated key** (compared case- and Unicode-folded) or a `tools/call` lookalike method gets `-32600`; an SDK-invalid request or a `tools/call` without a string `name` or with bad `arguments` gets `-32602`.
  - `tools/call` is its own `tool-call` kind with a required tool name, read from the raw own property. Every `tools/call` notification is dropped, as are invalid notifications and responses.
  - Refusing duplicate keys removes parser ambiguity, so bodies are forwarded byte-for-byte.
- **HTTP layer** ([ADR 021](../decisions/021-gateway-http-layer.md)): `POST /mcp` only. Checks run in a fixed order: path 404, method 405, auth 401 (`WWW-Authenticate: Bearer`, one answer for every reason), content type 415, size 413 (1 MiB), repeated session or protocol-version header 400, body read limit 413 (chunked), strict UTF-8 `-32700`, then `classifyBody` (`-32700`/`-32600` with HTTP 400, `-32602` with 200, dropped input 202).
  - An answer sent before the body is fully read uses a bounded lingering close: the answer is written, the rest of the body discarded for at most 1 s, then the connection closed.
- **Forwarding** (`src/forward.ts`): the body goes byte for byte (one leading BOM removed) with the gateway's own `Authorization` and an allowlist of client headers (`accept`, `mcp-session-id`, `mcp-protocol-version`). Only `content-type` and `mcp-session-id` come back, and the JSON or SSE body streams without buffering.
  - Network errors, refused redirects and the header timeout give a sanitized `-32603` with HTTP 502, as does a downstream 401/403 (the gateway credential refused). Client disconnects abort the downstream call.
- **Logging:** the shared stderr logger ([ADR 017](../decisions/017-shared-logger-service-tagging.md)), tagged `task2-mcp-gateway` or `mock-downstream`. One `request` line per request (`http_method`, `rpc_method`, `status`, `duration_ms`); no headers, bodies, tokens or URLs.

## Tradeoffs and limitations

- **The SDK HTTP transport answers some malformed input differently from what the gateway must return.** For example, valid JSON that is not JSON-RPC gets `-32700`, not `-32600`. The gateway therefore classifies envelopes itself (2.3) instead of relying on the downstream. The pinned SDK behavior is listed in ADR 018.
- **The downstream timeout covers only the wait for headers.** A long SSE stream is never cut, but a downstream that sends headers and then stalls holds the connection (tracked for 2.6).
- **POST only.** GET (server-to-client SSE stream) and DELETE (session end) get 405; the assessment needs POST and the mock is stateless (ADR 021).
- **A missing `Accept` cannot stay missing:** undici adds `*/*`, so the SDK downstream answers 406, which is relayed.
- **Until 2.5, every authenticated role can call every tool.** The admin gate plugs in on the `tool-call` kind before forwarding.

## Carried forward to 2.2 (resolved)

All four items from the 2.1 security review are handled in 2.2 (ADR 019):

- Constant-time comparison against every configured token: `authenticate`, with no early exit.
- More than one `Authorization` header is refused (`duplicate`).
- Credential-named fields are redacted by the shared logger (ADR 017).
- Placeholder or short tokens are accepted; `parseTokenConfig` returns a warning, which the 2.4 entry point logs at startup (owner decision).

## Carried forward to 2.4 (resolved)

All handled in 2.4 (ADR 021):

- The placeholder warning is logged at startup (`gateway.e2e.test.ts`).
- `consumeSecrets` deletes `GATEWAY_TOKENS` and `DOWNSTREAM_AUTH_TOKEN` from `process.env` after parsing (`gateway-config.test.ts`; the entry call is verified by review).
- Bodies are forwarded byte for byte with one leading BOM removed; two BOMs give `-32700`.
- Duplicate-key `-32600` gets HTTP 400 for every body shape.
- Strict UTF-8, the charset rule and the gateway's own `Content-Type` downstream are tested in `gateway.http.test.ts`.
- Dropped input gets HTTP 202 with no body and nothing forwarded (moved from the 2.5 list).

## Carried forward to 2.5

From the 2.3 security review, for the admin gate:

- Apply the tool-name pattern `^[A-Za-z0-9_.-]{1,128}$` before the admin check; names such as `constructor` or ones with lone surrogates reach the gate unchanged.
- Never look a tool name up on a plain object (`constructor`, `__proto__`).

## Carried forward to 2.6

From the 2.4 reviews, for downstream failure handling:

- Map downstream 5xx (and non-JSON error pages) to a sanitized `-32603` with HTTP 502 instead of relaying them.
- Bound a downstream that sends headers and then stalls (idle timeout on the stream).
